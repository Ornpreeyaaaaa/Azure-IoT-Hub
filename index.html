สถาปัตยกรรมศูนย์ข้อมูลค่าบริการใบรับรอง

อุปกรณ์ทุกชิ้นต้องผ่าน Hub ก่อน

Azure IoT Hub เป็นบริการแบบ managed ที่ Microsoft ดูแลโครงสร้างพื้นฐาน การอัปเดต และการขยายระบบให้ทั้งหมด ทีมพัฒนาจึงโฟกัสที่แอปพลิเคชันและการนำข้อมูลไปใช้ได้เต็มที่ เลื่อนลงเพื่อดูเส้นทางของข้อมูล

คุมอุปกรณ์ได้ทั้งทีละเครื่องและทีละพัน

สื่อสารสองทาง ทั้งขึ้นคลาวด์และสั่งกลับลงอุปกรณ์

Device Twin

เอกสาร JSON คู่ขนานบนคลาวด์ เก็บค่า desired, reported และ tag อ่านหรือตั้งค่าได้แม้อุปกรณ์ออฟไลน์ แล้วซิงก์เองเมื่อกลับมา

Direct Method

สั่งงานเรียลไทม์และรอผลตอบกลับทันที เช่น รีสตาร์ตเครื่อง หรือเปิด-ปิดวาล์ว

Jobs

อัปเดต configuration ให้เซนเซอร์หลายพันตัวพร้อมกัน กำหนดกลุ่ม ตั้งเวลา และติดตามความคืบหน้า

DPS

ติดตั้งแบบ zero-touch อุปกรณ์ใหม่เปิดครั้งแรกก็ลงทะเบียนกับ Hub ที่เหมาะสมให้อัตโนมัติ

0เก็บข้อความได้นานสุด
0พอร์ตเดียวก็เชื่อมได้ ผ่าน WebSockets

เลือกศูนย์ข้อมูลให้ดี ย้ายภายหลังไม่ได้

IoT Hub เป็นแบบ single-region ถ้าจะย้ายต้องสร้าง Hub ใหม่และย้ายการเชื่อมต่อของอุปกรณ์ทุกเครื่องเอง ปัจจัยตัดสินใจคือ latency, กฎหมายข้อมูล (เช่น PDPA), ค่าบริการ และที่ตั้งของบริการอื่นที่ใช้ร่วมกัน

ข้อดี

  • Managed service เต็มรูปแบบ ขยายระบบแค่เพิ่มหน่วย
  • ตัวตนและข้อมูลรับรองแยกรายอุปกรณ์ ยกเลิกสิทธิ์ทีละเครื่องได้ทันที
  • สื่อสารสองทางครบ ด้วย Twin, Direct Method และ Jobs
  • เชื่อมกับ Event Grid, Functions, Stream Analytics และ IoT Edge ได้ลึก
  • Zone redundant ไม่มีค่าใช้จ่ายเพิ่ม SLA 99.9%

ข้อเสีย

  • วางแผนขนาดและประเมินราคายาก ต้องดู meter, โควตา และ throttling
  • Vendor lock-in กับระบบนิเวศ Azure
  • ไม่ใช่ MQTT broker อิสระเต็มรูปแบบ
  • Single-region ต้องออกแบบระบบสำรองข้ามภูมิภาคเองผ่าน DPS
  • ไม่มี dashboard ในตัว และ roadmap ผลิตภัณฑ์เปลี่ยนแปลงได้
